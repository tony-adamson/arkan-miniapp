# Аркан — лендинг

Статический одностраничный лендинг проекта «Аркан» (ИИ-таролог в формате Telegram
Mini App). Собран по дизайн-системе проекта — [`design-system/`](../design-system/).

## Стек

Ничего, кроме HTML, CSS и одного файла на ванильном JS. Ни фреймворка, ни
рантайма Claude Design, ни React, ни внешних CDN — страница целиком открывается
с диска. Из инструментов только два python-скрипта без зависимостей: сборка
CSS-бандла и проверка контраста.

## Структура

```
site/                       ← корень сайта, это и деплоится
  index.html                  лендинг
  privacy/index.html          политика конфиденциальности (черновик, см. ниже)
  soon/index.html             заглушка «скоро» — временная цель CTA
  assets/
    css/tokens/*.css          токены дизайн-системы (исходники)
    css/app.css               компоненты и раскладка страницы (исходник)
    css/arkan.css             СОБРАННЫЙ бандл — его подключает HTML
    js/app.js                 тема + раскрытие карт
    fonts/*.woff2             20 локальных начертаний
    favicon.svg  apple-touch-icon.png  og.png
  robots.txt
tools/
  build-css.py                собирает assets/css/arkan.css
  contrast-check.py           проверка WCAG по фактическим парам вёрстки
  set-domain.sh               подстановка реального домена
  og/og.html                  шаблон OG-картинки
deploy/nginx.conf.example     пример конфигурации nginx
```

## Работа с проектом

CSS правится в `assets/css/app.css` и `assets/css/tokens/*.css`, после чего
бандл пересобирается:

```bash
python3 tools/build-css.py
```

Два гейта — оба возвращают ненулевой код, если что-то не так, и годятся для CI:

```bash
python3 tools/build-css.py --check && python3 tools/contrast-check.py
```

`--check` ловит правку исходника без пересборки (прод грузит только `arkan.css`).
`contrast-check.py` падает не только на низком контрасте, но и на паре, которую
не удалось вычислить, — переименованный токен не проскочит как «всё хорошо».

Прогон Lighthouse (цифры в таблице ниже получены так):

```bash
CHROME_PATH="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" npx --yes lighthouse@12 http://127.0.0.1:8765/ --chrome-flags="--headless=new"
```

Локальный просмотр — с http-сервера, а не через `file://` (пути к ассетам
абсолютные):

```bash
python3 -m http.server 8765 --directory site
```

## Перед деплоем — обязательно

1. **Домен — подставлен.** Сайт собран под `arkana.hoapps.dev`: canonical, OG,
   Twitter Card и `deploy/nginx.conf`. Сменить домен можно в любой момент,
   скрипт запускается повторно:

   ```bash
   tools/set-domain.sh новый-домен.ru
   ```

   Он правит страницы на месте, а из `deploy/nginx.conf.example` создаёт
   `deploy/nginx.conf`, не трогая шаблон.

2. **Ссылка на бота.** Обе кнопки «Открыть в Telegram» ведут на `/soon/`.
   Когда бот появится, заменить `href="/soon/"` на `https://t.me/<bot>` в
   `site/index.html` (два места).

3. **Политика конфиденциальности.** `site/privacy/index.html` — цельный
   нейтральный текст: он описывает сервис по его устройству и не содержит
   реквизитов оператора. Юристом не проверялся. Публиковать можно только после
   трёх действий:

   - заменить `[адрес для запросов]` (два места в тексте) на рабочий контакт —
     без него у пользователя нет способа реализовать свои права по 152-ФЗ;
   - сверить раздел 6 с реальностью: какой поставщик языковой модели используется
     и в какой юрисдикции он обрабатывает запросы;
   - сверить раздел 7: там сказано, что базы с персональными данными граждан РФ
     находятся на территории РФ — это должно быть правдой на момент публикации.

   Разделы 2 (сайт ничего не собирает), 3, 4, 5, 8–11 проверять не нужно: они
   описывают то, что верно по устройству сервиса. По Положению конкурса
   ответственность за законность обработки персональных данных лежит на
   участнике.

4. **Год в футере** захардкожен: `2026`, три места (`index`, `privacy`, `soon`).

## Деплой

Сайт статический. Заливать не поверх живого каталога: `--delete` создаёт окно,
в котором старые ассеты уже удалены, а новые ещё не приехали, и посетитель ловит
страницу без стилей. Атомарно — через каталог с версией и подмену симлинка:

```bash
rsync -av --delete site/ user@vps:/var/www/arkana-new/ && ssh user@vps 'ln -sfn /var/www/arkana-new /var/www/arkana && nginx -t && systemctl reload nginx'
```

`root` в конфиге указывает на симлинк `/var/www/arkana`; откат — переключение
симлинка на предыдущий каталог.

Презентация `deck/` из корня репозитория публикуется в том же релизе по адресу
`/deck/`: отдельного `location` нет, её отдаёт общий `location /`, а шрифты и favicon
она берёт у лендинга по абсолютным путям `/assets/...`. Поэтому в каждый релиз её
нужно докладывать после `site/` и до переключения симлинка — иначе `rsync --delete`
создаст релиз без презентации:

```bash
rsync -av ../deck/ user@vps:/var/www/arkana-new/deck/
```

Конфигурация веб-сервера — `deploy/nginx.conf.example`; класть в
`/etc/nginx/conf.d/arkan.conf` (файл начинается с директив уровня `http`,
заменить им весь `nginx.conf` нельзя). Внутри: редирект на HTTPS, gzip
(brotli закомментирован — включить, если собран `ngx_brotli`), кеширование
шрифтов на год, CSP и остальные security-заголовки.

Заголовки задаются **только на уровне `server`**, а `Cache-Control` считается
через `map`: любой `add_header` внутри `location` отменил бы наследование всех
`add_header` из `server`, и CSP перестал бы доходить до ответов. Не добавляй
`add_header` в `location`, не продублировав там же весь набор.

`http2` намеренно записан старым синтаксисом `listen 443 ssl http2` — директива
`http2 on;` появилась только в nginx 1.25.1 и роняет конфиг на стоковых сборках
Debian/Ubuntu. HSTS выставлен без `includeSubDomains`: поддоменов пока нет, а
директива необратима на весь `max-age`.

Сертификат — certbot с автопродлением. Домен заведён в Cloudflare, и здесь есть
развилка: при включённом проксировании (оранжевое облако) TLS терминирует
Cloudflare, поэтому режим шифрования должен быть **Full (strict)**, а на origin
нужен валидный сертификат — либо Cloudflare Origin Certificate, либо Let's Encrypt
через DNS-01 (HTTP-01 за проксёй тоже проходит, но зависит от того, что
`/.well-known/acme-challenge/` не перехвачен правилами). При DNS-only (серое
облако) достаточно обычного `certbot --nginx -d arkana.hoapps.dev`.

После деплоя проверить, что заголовки действительно доходят:

```bash
curl -sI https://arkana.hoapps.dev/ | grep -iE 'content-security-policy|cache-control'
```

## Проверки

Прогнаны на локальном сервере (`python3 -m http.server`, то есть без gzip —
на nginx показатели будут не хуже):

| Проверка | Результат |
| --- | --- |
| Контраст (`tools/contrast-check.py`) | 44 сравнения (19 пар × 2 темы), все ≥ порога |
| Переполнение на 320/360/390/430/768/1024/1280 | горизонтального скролла нет, элементов за полями нет |
| Lighthouse, десктоп | Perf 100, A11y 100, BP 100, SEO 100 |
| Lighthouse, мобильный | Perf 98, A11y 100, BP 100, SEO 100 (LCP 2.1 s, CLS 0, TBT 0) |
| Внешние запросы | нет: в консоли только локальные ресурсы |

Lighthouse дополнительно нашёл два дефекта, которых не было в списке правок, —
оба исправлены:

- подпись позиции под картой (`ПРОШЛОЕ`/`СЕЙЧАС`/`ШАГ`) лежит поверх
  декоративного свечения hero, а не на голом фоне: на нём `--text-tertiary`
  давал 4.13:1. Заменён на `--text-secondary` (6.5:1);
- `aria-label` кнопок не включал их видимый текст (WCAG 2.5.3 Label in Name).
  Кроме того, лицевая грань карты скрыта поворотом, но её текст считался
  видимым — теперь у закрытой карты она `visibility: hidden`.

Конфиг nginx **не валидирован исполнением** — `nginx` в среде разработки
отсутствует. До применения на сервере обязательно `nginx -v && nginx -t`.

Что осталось непроверенным: `prefers-reduced-motion` подтверждён только
статически (правила в бандле: деградация токенов в `motion.css`, обрыв
бесконечных анимаций в `base.css`, кроссфейд граней вместо переворота в
`app.css`), рантайм-проверка с включённой системной настройкой не делалась.
Отображение в webview Telegram (P2-9) не проверялось — нужен опубликованный
домен.
